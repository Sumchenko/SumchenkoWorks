# Sumchenko Works — сайт-портфолио

Статический сайт без сервера и сборки. Визуальный язык — дизайн-система Sumchenko Works (`_ds/`).

## Запуск

Сайт нужно открывать через любой статический веб-сервер (не через `file://`):

```
python3 -m http.server 8080
# или
npx serve .
```

Затем откройте `http://localhost:8080/Sumchenko%20Works.dc.html`.

## Маршруты

| Адрес | Страница |
|---|---|
| `#/` · `?to=approach\|featured\|skills\|contacts` | Единая главная страница: Главная, Подход, Избранное, Навыки, Контакты. Верхнее меню прокручивает к разделам |
| `#/works` · `?cat=dev&tech=go&q=…` | Каталог всех проектов (из «Избранного» открывается в новой вкладке) |
| `#/works/<id>` · `?tab=arch` · `?tab=artifacts&doc=<artifactId>` | Проект: вкладки «Обзор», «Архитектура», «Артефакты»; артефакт открывается в окне просмотра |
| всё остальное | 404 |

Старые адреса `#/architecture/…` и `#/artifacts/…` перенаправляются в соответствующий проект, `#/about` — на главную.

## Файлы

- `Sumchenko Works.dc.html` — оболочка: навигация, маршрутизация, тема, загрузка данных, 404, футер, уведомления, заголовки и метаданные страниц.
- `Home`, `Works`, `Project` (`.dc.html`) — страницы.
- `ProjectCard`, `ArtifactRow`, `ArtifactViewer`, `ErdView`, `FlowView` (`.dc.html`) — переиспользуемые компоненты.
- `data/content.js` — **весь контент**. Интерфейс ничего не хранит сам.
- `data/store.js` — доступ к данным: поиск, фильтры, связи, view-модели.

## Контент

Все проекты, разборы и артефакты — **демонстрационные** (`demo: true`) и помечены на сайте.

Модели в `data/content.js`:

- `projects` — проект. Обязательны `id, code, title, category, status, year, tech, summary, cover`. Остальные поля (`problem`, `requirements`, `architecture`, `dataModel`, `api`, `decisions`, `stages`, `results`, `related` …) необязательны: пустые блоки не показываются, а вкладки «Архитектура» и «Артефакты» скрываются, если для них нет данных.
- `diagrams` — схемы трёх видов: `components` (изометрическая схема), `erd`, `flow`. Проекты, разборы и артефакты ссылаются на них по `id`.
- `architecture` — архитектурные разборы проекта (потоки данных, интеграции, компромиссы); показываются на вкладке «Архитектура» проекта, указанного в `project`.
- `artifacts` — материалы. `view` определяет просмотрщик: `doc` (поле `body`), `code` (`source`), `erd` / `components` / `flow` (`diagram`), `image` / `pdf` (`src`), `link` (`href`).
- `categories`, `statuses`, `technologies`, `artifactTypes`, `archKinds` — справочники для фильтров.
- `profile` — блоки «кто я», «Навыки» и «Контакты» на главной. Поля со значением `null` показываются как «не указано»; разделы с `placeholder: true` помечены «Заглушка». Заполните их, чтобы метки исчезли.

Чтобы добавить проект, допишите объект в `projects` (и при необходимости диаграммы и артефакты). Страницы менять не нужно.

## Подключение API или CMS

Замените `SWStore.source` в `data/store.js` на функцию, возвращающую Promise с объектом той же структуры:

```js
SWStore.source = () => fetch('/api/content').then((r) => r.json());
```

Состояния загрузки и ошибки (с кнопкой «Повторить») уже обрабатываются оболочкой.
