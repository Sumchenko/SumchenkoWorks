HTTP API для управления целями мониторинга. Работает на том же сервере, что и веб-интерфейс, и под той же авторизацией.

## Доступ

- Всё, кроме `/healthz`, — за Basic Auth (`ADMIN_USER` / `ADMIN_PASSWORD`). Без пароля — 401.
- Запросы с чужих сайтов отклоняются (`http.CrossOriginProtection`, Go 1.25) — 403. Браузер сам подставляет Basic Auth, поэтому без этой защиты любая страница могла бы удалить цель. Запросы без заголовков `Origin` / `Sec-Fetch-Site` (curl, скрипты) пропускаются.
- `GET /healthz` открыт: пингует базу и отвечает 200 или 503 — для HEALTHCHECK в Docker и внешнего мониторинга.

## Эндпоинты

| Метод | Путь | Что делает | Ответы |
| --- | --- | --- | --- |
| GET | `/api/targets` | Все цели со статусом | 200 |
| POST | `/api/targets` | Создать цель | 201, 400, 422 |
| GET | `/api/targets/{id}` | Одна цель со статусом | 200, 404 |
| PUT | `/api/targets/{id}` | Заменить цель целиком | 200, 400, 404, 422 |
| DELETE | `/api/targets/{id}` | Удалить цель вместе с историей | 204, 404 |

После любого изменения планировщик применяет его сразу, не дожидаясь периодического перечитывания.

## Цель

| Поле | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `name` | string | — | Название в интерфейсе, обязательно |
| `url` | string | — | `http(s)://…`, обязательно |
| `expected_status` | int | любой 2xx | Ожидаемый код после редиректов, 100–599 |
| `keyword` | string | нет | Строка, которая должна быть в первом мегабайте ответа, с учётом регистра |
| `headers` | object | `{}` | Заголовки запроса, например `apikey` для Supabase; хранятся открытым текстом |
| `interval_seconds` | int | `CHECK_INTERVAL` (60 с) | Не меньше 30 с |
| `timeout_seconds` | int | `CHECK_TIMEOUT` (15 с) | Не больше 120 с и меньше интервала |
| `enabled` | bool | `true` | Выключенная цель не проверяется, история сохраняется |

## Статус в ответе

| Поле | Смысл |
| --- | --- |
| `state` | `up`, `down`, `pending` (проверок ещё не было) или `disabled` |
| `last_checked_at` | Время последней проверки |
| `status_code` | HTTP-код; нет, если ответа не было |
| `response_time_ms` | Время до конца чтения тела — ближе к тому, что видит пользователь |
| `error` | Причина падения: сетевая ошибка, неожиданный код, нет ключевого слова |
| `uptime_24h` | Доля успешных проверок за сутки, % |

Реальный ответ для цели «Mito»:

```json
{
  "id": 3,
  "name": "Mito",
  "url": "https://mito.13-143-64-158.sslip.io/",
  "keyword": "Mito",
  "interval_seconds": 30,
  "timeout_seconds": 15,
  "enabled": true,
  "status": {
    "state": "up",
    "last_checked_at": "2026-10-12T21:20:34.109818Z",
    "status_code": 200,
    "response_time_ms": 85,
    "uptime_24h": 100
  }
}
```

И статус упавшей цели:

```json
{
  "state": "down",
  "last_checked_at": "2026-10-12T21:20:34.128419Z",
  "response_time_ms": 446,
  "error": "Get \"https://old-demo.sumchenko-tech.ru/\": remote error: tls: internal error",
  "uptime_24h": 0
}
```

## Ошибки

| Код | Когда | Тело |
| --- | --- | --- |
| 400 | Невалидный JSON или неизвестное поле | `{"error": "некорректный JSON: json: unknown field \"color\""}` |
| 401 | Нет пароля или он неверный | — |
| 403 | Межсайтовый запрос | — |
| 404 | Цели с таким id нет | `{"error": "цель не найдена"}` |
| 422 | Настройки не прошли проверку — перечислены все проблемы сразу | `{"errors": ["интервал должен быть не меньше 30 с", "таймаут (15 с) должен быть меньше интервала (10 с)"]}` |

**Почему так.** Неизвестные поля — ошибка, а не молчаливый пропуск: опечатка в имени поля иначе превратилась бы в «значение по умолчанию». Ошибки валидации возвращаются списком, чтобы исправить всё за один заход. `PUT` заменяет цель целиком — у частичного обновления неоднозначно, что значит отсутствующее поле.
